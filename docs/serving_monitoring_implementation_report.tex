\section*{Executive Summary}
This implementation adds the missing serving and monitoring controls required for the SpotyBoys ML systems project while preserving the current Navidrome-first serving design. The work adds a real fallback state machine, actionable degraded mode, durable PostgreSQL serving telemetry, manual serving-monitor and rollback workers, a promotion gate before serving refresh, and an additive Grafana dashboard. Auto rollback remains disabled by default and all monitoring writes are non-fatal to recommendation serving.

\section*{What Was Implemented}
\begin{itemize}[leftmargin=*]
  \item A durable monitoring schema for request metrics, rollups, decisions, and active model versions.
  \item Postgres and in-memory repository methods for all monitoring and decision records.
  \item A serving fallback state machine with states \texttt{healthy}, \texttt{model\_degraded}, \texttt{model\_unavailable}, \texttt{catalog\_insufficient}, \texttt{navidrome\_degraded}, and \texttt{fallback\_only}.
  \item Degraded mode that changes recommendation behavior to safe fallback serving and exposes the action in API responses.
  \item Manual workers for rollup generation and rollback checks.
  \item A promotion gate requiring a valid bundle and approved \texttt{promotion\_decision.json}, with explicit override via \texttt{SPOTIBOYS\_ALLOW\_UNAPPROVED\_REFRESH=true}.
  \item Additive Grafana dashboard \texttt{serving\_monitoring.json}; existing dashboards were not replaced.
\end{itemize}

\section*{Fallback State Machine}
The state machine is defined in \texttt{packages/recommendation\_engine/serving\_state.py}. It derives state from bundle availability, pipeline exceptions, ranked output, playable catalog size, returned item count, and model status. The recommendation path catches pipeline exceptions and returns deterministic playable fallback items instead of crashing. API responses expose \texttt{fallback\_level}, \texttt{fallback\_state}, \texttt{degraded}, \texttt{degraded\_reason}, and \texttt{degraded\_action}.

\section*{Degraded Mode}
The endpoint \texttt{POST /admin/model-status} is protected by the existing admin/session auth helper. When degraded mode is enabled, the recommendation service uses safe fallback serving and marks responses as degraded. The current degraded state and action appear in \texttt{/monitoring/summary}.

\section*{Serving Metrics Schema}
\texttt{app.serving\_request\_metrics} stores per-request operational telemetry. \texttt{app.serving\_metric\_rollups} stores time-windowed aggregates. \texttt{app.model\_trigger\_decisions} stores promotion, rollback, and degraded-mode decisions. \texttt{app.model\_versions} stores active and previous-good model metadata. These tables are derived monitoring tables and do not replace raw playback or feedback events.

\section*{Serving Monitor Worker}
Run manually:
\begin{lstlisting}[language=bash]
python workers/serving-monitor-worker/rollup_metrics.py --window 5m --window 1h --print-json
\end{lstlisting}
Expected output is JSON with fields such as \texttt{request\_count}, \texttt{fallback\_rate}, \texttt{error\_rate}, \texttt{p95\_latency\_ms}, and \texttt{sample\_status}. With too few requests, \texttt{sample\_status} is \texttt{insufficient}.

\section*{Rollback Evaluator}
Run manually:
\begin{lstlisting}[language=bash]
python workers/rollback-check-worker/check_rollback.py --window 5m --print-json
\end{lstlisting}
The evaluator reads the latest rollup, active model, and previous-good model. It writes a decision to \texttt{app.model\_trigger\_decisions}. Auto rollback is disabled by default; the default behavior is a manual recommendation only.

\section*{Promotion Gate}
The promotion gate checks bundle validity and \texttt{promotion\_decision.json}. Missing or blocked promotion decisions stop activation unless:
\begin{lstlisting}[language=bash]
export SPOTIBOYS_ALLOW_UNAPPROVED_REFRESH=true
\end{lstlisting}
Successful refresh records the active model version. Failed refresh records a \texttt{promotion\_gate} block decision where the API can reach the repository.

\section*{Grafana Dashboard}
The new dashboard is \texttt{infra/grafana/dashboards/serving\_monitoring.json}. It uses datasource \texttt{spotiboys-pg} and queries the real \texttt{app.*} monitoring schema for active model, degraded status, fallback rate, error rate, p95 latency, outcome rates, rollback decisions, and promotion decisions. Existing dashboards remain unchanged.

\section*{Expected Outputs}
\begin{itemize}[leftmargin=*]
  \item Recommendation response includes \texttt{fallback\_state}, \texttt{fallback\_level}, \texttt{degraded}, \texttt{degraded\_reason}, and \texttt{degraded\_action}.
  \item Rollup worker prints JSON. In a cold demo it should say \texttt{"sample\_status": "insufficient"} rather than crashing.
  \item Rollback worker prints \texttt{no\_action} for insufficient samples and \texttt{recommend\_rollback} or \texttt{mark\_degraded} for threshold breaches with enough requests.
  \item Promotion refresh with missing or blocked decision fails unless \texttt{SPOTIBOYS\_ALLOW\_UNAPPROVED\_REFRESH=true}.
\end{itemize}

\section*{Known Limitations}
\begin{itemize}[leftmargin=*]
  \item Auto rollback is intentionally not mutating serving bundles by default.
  \item The rollup worker computes outcome metrics only from events available in the current schema.
  \item The dashboard requires the new schema to be initialized in Postgres before panels return data.
  \item Promotion decisions must be emitted by the training pipeline or created locally for candidate bundles; override is explicit and opt-in.
\end{itemize}
