错误核心是：

  psycopg2.errors.InsufficientPrivilege: could not open file "base/16384/1255": Permission denied

  PostgreSQL 容器内以 postgres 用户（UID 999）运行，但 /mnt/mlflow_persist/postgres_data 目录是 cc 用户（UID
  1000）所有，导致写入系统表时权限不足。

  修复：

  sudo chown -R 999:999 /mnt/mlflow_persist/postgres_data
  docker restart postgres

  等 postgres 重启后验证：

  docker logs postgres --tail 5

  看到 database system is ready to accept connections 后重新训练：

  uv run python -m src.ranker.train 2>&1 | tee logs/ranker_train.log


按流水线顺序，从上游到下游：

  ---
  Item2Vec（Stage B）

  对整个系统影响最大，所有下游都依赖这个嵌入质量。

  │ vector_size │ 128  │ 增大→表达力更强，但内存和计算成倍增加 │
  ├─────────────┼──────┼───────────────────────────────────────┤
  │ window      │ 10   │ 增大→捕捉更远的上下文关系             │
  ├─────────────┼──────┼───────────────────────────────────────┤
  │ negative    │ 15   │ 增大→训练更稳定，但变慢               │
  ├─────────────┼──────┼───────────────────────────────────────┤
  │ min_count   │ 5    │ 减小→保留更多长尾曲目                 │
  ├─────────────┼──────┼───────────────────────────────────────┤
  │ epochs      │ 10   │ 增大→收敛更充分                       │
  └─────────────┴──────┴───────────────────────────────────────┘

  ---
  优先级建议

  影响最大的几个，按投入产出比排：

  1. Item2Vec window / epochs — 嵌入质量是整个系统的地基
  2. Ranker N_HARD — 硬负样本质量直接影响排序效果
  3. L（前缀长度） — 更长的上下文 vs 更多 padding 噪声的权衡
  4. Ranker lr / epochs — 最直接能观察到 NDCG@5 变化的地方
